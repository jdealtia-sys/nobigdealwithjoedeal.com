# Session 2026-09-09 — Credential badges, and closing the GBB audit's tracked follow-ups

Two threads, same session. Uncommitted at session end — working tree only.

## 1. GAF / TAMKO / American Operator credential badges on generated documents

Jo: *"can you make sure every doc we generate in the CRM has all 3 icons inside
correct? im thinking of GAF, TAMKO, and local operator."* Then, after the first
pass shipped text-only: *"make sure we have my GAF and TAMKO ID#s under both
not just the emblem."*

**Found:** the CRM already had a GAF/TAMKO "affiliates" credential system
(`company-profile.js` + `affiliateRow()` in `document-generator-templates.js`)
— but `affiliateRow()` was defined and never called from any render function
(the "features exist but are unmounted" pattern this vault has flagged
before), and it only ever rendered plain text (name + license number), never
the actual badge artwork. There was also no "local operator" credential at
all — NBD's real one is the American Operator "Locally Owned & Operated"
certification, already used on the public site (`docs/assets/american-operator/`)
but never wired into CRM documents.

**Built:**
- Real badge artwork (not text) embedded as data URIs — [nbd-badge-assets.js](../../docs/pro/js/nbd-badge-assets.js),
  generated by [scripts/build-badge-assets.js](../../scripts/build-badge-assets.js)
  from the committed PNGs, same technique as the existing NBD-logo data URI
  (the doc viewer's srcdoc iframe + CSP object-src block a linked `<img
  src="/assets/...">`). GAF's `#1162011` and TAMKO's `#181382` print under
  their emblems (American Operator has no member number — the artwork
  itself says "Certified").
- `affiliateRow()` wired into 21 client-rendered document types where it's
  actually relevant per the NBD Document Standard's own section 5 (contracts,
  estimates, closeout docs, reports, marketing pieces) — explicitly NOT on
  adjuster/insurance-facing paperwork (inspection-for-insurance, claim guide,
  supplement request, assignment of benefits, the storm history report,
  which is built to hand to an adjuster despite nominally being a "report"),
  and not on the small referral card (kept deliberately uncluttered).
- The SAME gap existed independently in the **server-side Puppeteer/Handlebars
  PDF pipeline** (`functions/print/*.hbs`) — contract, invoice, change order,
  receipt, warranty, and estimate PDFs were headed toward the same
  no-badges fate on a completely separate render path. New shared partial
  [affiliateRow.hbs](../../functions/print/partials/affiliateRow.hbs), matching
  CSS in `design-system.css`. Real `https://` URLs there, not data URIs —
  Puppeteer fetches network resources fine; the srcdoc/CSP constraint is
  browser-only.
- Non-NBD tenant safety verified, not assumed: a stranger tenant still gets
  nothing unless it sets its own `affiliates` — extended the existing
  `tenant-brand.test.js` M1 blanking assertion to cover the third badge.

Verified: rendered real HTML output and screenshotted it (warranty
certificate, door hanger, neighborhood mailer) — clean, centered, badges +
license numbers both visible. Full touched-suite run green: `docgen-brand`,
`docgen-render`, `tenant-brand`, `render-pdf-neutral-fallback`, plus the
3810-assertion `smoke.test.js`.

## 2. GBB audit — tracked follow-ups closed

See [GBB-TIER-SOURCE-OF-TRUTH-2026-09-09](../audit/GBB-TIER-SOURCE-OF-TRUTH-2026-09-09.md)
§9 "Tracked as follow-ups" for the full context — that audit and PR #1529
were already merged to `main` before this session (confirmed:
`fix/gbb-tier-consolidation`'s tip has an IDENTICAL tree to the squash-merge
commit `20c990f9`, so nothing from that branch was stranded). Jo: *"lets
also make sure when we give warranties, receipts, they need to match their
estimates / docs / etc — like matching tiers, warranties, and more... make
sure it all ties properly."*

Closed this session, all with tests green:
- **`customer-estimate-rows.js`** (both the `docs/pro/js/` browser copy and
  its byte-identical `functions/` mirror — drift-guard test still passes)
  was still printing "Better tier" on invoices/receipts — capitalizing the
  raw internal key instead of the customer-facing label. Now reads a
  3-entry `{good:Standard, better:Preferred, best:Elite}` map (no shared
  config import: this file has to run in both the browser, which has
  `estimate-config.js`, and `functions/`, which has neither `window` nor
  that file). Updated the one pinned test that baked in the stale string.
- **Contract warranty-bridge gap** — `doc-preflight.js`'s `contract` schema
  collected `warrantyTier` but never bridged it to the free-text `warranty`
  field `functions/print/templates/contract.hbs` needs (`{{#if
  warranty}}` — silently drops the entire Warranty section when null).
  Client-side `renderContract` was never affected (reads `warrantyTier`
  directly); this was purely for the server PDF path, currently masked by
  an unrelated pre-existing `paymentSchedule.map` crash the audit flagged
  as needing "fix both together" — leaving that crash untouched, so this
  is a pure, currently-inert-in-practice correctness fix, not a behavior
  change today. Bridges via `window.NBD_ESTIMATE_CONFIG.tierWarrantyText()`
  when loaded (dashboard.html), falls back to an inline copy of the same
  three strings when not (customer.html never loads `estimate-config.js`)
  — verified both paths produce byte-identical text via a vm-sandbox probe.
- **Receipt balance section** defaulted to blank (`contractTotal` field
  sourced `'literal:'`) even when the job's real total was already known —
  a rep had to remember and retype it. Now pre-fills from
  `computed.jobValue`, the same canonical total every other doc type reads;
  still clearable to omit the balance section, per the field's own
  existing design intent. Confirmed the fill-form's `source:` resolution
  is a different code path than `hydrateDerivedFields()`, so the existing
  "no contract total → no balance section" contract test was unaffected.
- **Rep training** (`academy-insurance-tree-data.js`) had three scripted
  dialogue lines teaching reps to tell a real homeowner "you have a 5-year
  workmanship warranty" — now say lifetime, matching what's on the actual
  documents reps hand over.
- **Seed-demo data** (`functions/seed-demo.js`) — confirmed live in prod per
  `STABILITY-AUDIT-2026-09-04.md` — still had the retired "Standard
  Reroof"/"Reroof Plus"/"Full Redeck" vocabulary on its six demo estimates.
  Now Standard/Preferred/Elite.

**Two items needed Jo's call, not a code fix — asked directly, both resolved:**
- `docs/blog/architectural-shingles-vs-3-tab.html` (his own byline) had a
  section literally titled "When 3-Tab Is the Right Call," recommending
  3-tab for homeowners selling soon, rental properties, or tight budgets —
  directly contradicting the "NBD never installs 3-tab on a new roof"
  policy the estimate tool now enforces. **Decision: the policy is right,
  the post was wrong.** Rewrote the section (now "When to Keep It Simple
  (Without Going Backward)") to recommend the Standard architectural tier
  in those same situations instead of 3-tab, explicitly naming that NBD
  doesn't install 3-tab anymore and why — kept in Joe's first-person,
  straight-talk voice rather than softened into generic copy. Also fixed
  the "Quick Reference" table's two rows that still said 3-tab. Every
  remaining 3-tab mention in the piece is now purely comparative/historical
  ("here's what it is, here's why it's worse"), never a recommendation to
  install it.
- The Pledge's "Two Layers" pitch (`docs/the-pledge/index.html`) had Layer
  2 built entirely on "even after your workmanship warranty's clock has run
  out, I'll still come look" — but workmanship is lifetime on every tier
  now, so there's no clock left to run out. **Decision: reframe, don't
  retire.** Layer 2 now reads "whenever you call — whether or not the
  issue turns out to be something a written warranty covers — I'll still
  come look... covered by warranty, I fix it; not our work, I'll quote the
  fix fairly." This turned out to already match, word-for-word in spirit,
  the page's own pre-existing "THE PROMISE" section higher up
  (`if it's something I caused... If it's not, I'll quote the fix
  fairly`) — the Layer-2 card just hadn't caught up to what the rest of the
  page already correctly said. No contradiction left on the page after the
  edit (verified via full page-text read).
