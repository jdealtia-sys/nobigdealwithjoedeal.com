- **#1599** — the-nbd-guarantee/the-nbd-build's tier-pricing copy claimed Preferred/Elite cost +15%/+30% over Standard; the real catalog rates (`estimate-config.js`'s `TIER_RATES`) compute +9%/+21%. - **#1600** — Close Board's `deleteDeal()` removed `deal_rooms/{dealId}` but never touched the `deal_accept_tokens` minted for it. Fixed with existence checks (inside the Firestore transaction for the accept path, so a concurrent delete forces a retry instead of a race) and `update()` instead of `set(merge)` as defense-in-depth.

- **#1603** — `#photosByPhase` silently rendered empty for a company_admin/manager/viewer opening a teammate's lead — a third hand-rolled `where(userId==)` copy of a query the codebase had already fixed twice elsewhere. Pointed at the shared `_photoQueryScopes` helper instead.
- **#1604** — every native HEIC/HEIF/TIFF/AVIF photo (AirDrop, Files-app drag-drop, drone output, non-auto-converting iOS Safari) has been uploading with **zero EXIF/GPS** since this code was written: the fallback parser lazy-loaded `exifr` from `cdn.skypack.dev`, an origin never in the CSP's `script-src-elem` allowlist — confirmed against the live header, not assumed. Self-hosted at `docs/assets/vendor/exifr/exifr.esm.mjs` (npm `exifr@7.1.3`'s own zero-dependency `module` build, copied verbatim) instead of allowlisting a new CDN.
- **#1605** — `/inspect`'s photo input has never actually transmitted the attached files — only a filename/count text summary — and the success message said nothing about it, reading as if the photos went through. Added a disclosure, shown only when the homeowner actually attached something.
- **#1606** — `docs/admin/project-codex.html` had two unrelated UI groups (search-filter buttons, Session Form fields) coincidentally sharing an `sf-` prefix, four ids colliding outright. Renamed the button group to `flt-*`; the form fields (actively read by `getElementById`) were left untouched.
- **#1607** — `stormWatch`'s subscriber query had no `.where('active','==',true)` filter, unlike its sibling `checkStormAlerts` cron — an opted-out homeowner kept receiving `stormWatch`'s texts after unsubscribing.
- **#1608** — `tests/warranty-claim.test.js`'s mutation self-check built its "gate removed" target string with literal `\n`, but the source file is CRLF — the `.replace()` silently no-op'd, so the mutation never ran and the whole suite was a **vacuous gate** wearing a green check mark. Two independent, now-superseded attempts at this exact fix already existed as open PRs from an earlier session (see "left open" below) — this one, done live in a peer Claude session Jo approved directly, is the one that actually landed.
- **#1609** — the customer.html "duplicate photo fetch" item, explicitly deferred out of the batch above and scoped separately afterward (a 3-agent parallel research pass over both loaders, `photoDocToView`'s transform, `NBDIDBCache`'s revalidate contract, and every consumer of both `window._customerPhotos` and `window._allPhotos`). `loadPhotos()` (`#photoList`) and `loadPhotosByPhase()` (`#photosByPhase`) each ran their own `getDocs()` against the identical query on every lifecycle event; now share one fetch via in-flight de-dup, with a new `loadAllCustomerPhotos()` firing both concurrently (`Promise.all`) at the two points that need both views. Each loader's own transform/render/cache stayed untouched. **Found and fixed in passing:** the delete handlers' refresh call was a bare `loadPhotos(...)` — module-scoped in an ES module, called from a separate classic script — throwing `ReferenceError` every single time, silently swallowed by an empty `catch`. The overview strip has never actually refreshed after a delete until this PR.
