## Cross-cutting facts the critic verified (do not re-litigate)

- **Zapier's Webhooks app is a PAID-plan feature.** The research note's
  "Zapier (100 tasks/mo free)" route does not exist on the free plan. The $0
  routes are Make, n8n, Pipedream and Google Apps Script.
- **`SLACK_WEBHOOK_URL` is the `__unset__` stub** — every Slack post in the
  repo is dark, and has been since it shipped.
- **Not enabled on `nobigdeal-pro`:** vision, analyticsdata, searchconsole,
  drive, sheets. Each needs an Owner to run `gcloud services enable`; the
  deploy service account cannot (it lacks `roles/serviceusage.serviceUsageAdmin`).
- **CI deploys `firestore.rules` but NOT `firestore.indexes.json`.** A new
  composite index passes every local check and then throws
  `FAILED_PRECONDITION` in production. Design around it (equality-only query +
  in-memory filter) or ship the index by hand first.
- **Hosting's `**` headers do NOT override function-set headers** on a rewrite
  — probed live against `/report/`. A function's own `Cache-Control` wins.
- **`Authorization: Bearer` passes through to a gen2 function** rather than
  being intercepted by Google — probed, not assumed.
- **`documentation/architecture/THUMBTACK-WEBHOOK-2026-08.md` is WRONG** where
  it says bridged leads page Jo. No `lead-alert` trigger exists on
  `thumbtack_leads`, `KIND_LABEL` has no entry, and `push-functions.js`
  returns early unless `assignedTo` is set — which `mapPublicLeadToLead`
  never sets. (Handoff item 10.)
- **A `FUNCTIONS_INDEX.md` row is mandatory for every new export** —
  `tests/smoke/dashboard.test.js` scans `index.js` and every
  `Object.assign(exports, X)`-mounted module and demands one. Three maps
  missed this.
- **The deploy discovers targets by grepping `^exports\.NAME = onCall(`** at
  line start. Any other export form never deploys, and the orphan gate then
  fails the deploy as MISSING.

## Generic tokenized inbound-lead webhook

**Status: OPEN** · size M — Two new functions + two new triggers + rules + alert wiring + a node suite and rules assertions + a small settings row across ~9 shared files; no vendor SDK, no secret, no CSP — but it is wiring in the two most collision-prone modules (lead-bridge/lead-alert/integrationStatus), not a copy of thumbtack.js.

Jo gets one always-on HTTPS endpoint (inboundLeadWebhook) that any no-code tool can POST a lead to with a per-tenant token he mints from the CRM settings page in one click; the lead lands in webhook_leads, is mirrored into the pipeline by the existing lead-bridge, and — only if the new leadAlertWebhook trigger is built, which the Thumbtack template does NOT have — pages him by SMS/email like a website lead. No vendor, no secret, no CSP change; nothing flows until Jo mints a token and builds the Zap.

**Value with zero Jo-side setup:** Zero Jo-side Firebase/CLI setup: no defineSecret, no `functions:secrets:set`, no deploy-time stub. After merge+deploy the endpoint exists and answers 401 to everything (safe), integrationStatus reports inboundWebhook:false, and the settings row shows 'Not configured — Generate'. Nothing flows until Jo (1) clicks Generate in CRM Settings and (2) builds the Zap/scenario/Apps Script that POSTs to the URL with the header — so the honest answer is: the plumbing is dark until Jo does a ~10-minute config task in the CRM plus Zapier/Make/Google Forms, and every lead thereafter is free on our side. Tenants get the same self-serve path with no NBD involvement.

**Data model:** inbound_webhook_tokens/{sha256hex(token)} — admin-SDK only: { companyId: string (tenant; NBD = Joe's uid '1phDvAVXHSg82wDLegAbQFq14Ci1'), ownerUid: string, label: string ≤60, status: 'active'|'revoked', defaultSource: string, ackHomeowner: false, createdAt, createdBy: uid, revokedAt?, lastUsedAt?, useCount?: number }. Plaintext token (64 hex chars, 256 bits) is returned once by the onCall and never stored. One active token per companyId (rotation revokes the rest).
webhook_leads/{'wh_'+sha256(companyId+':'+(externalId||canonical payload)).slice(0,32)} — admin-SDK only landing doc, same role as thumbtack_leads: { source, companyId (from the token doc only), tokenHash (12-char prefix, audit), isTest: bool, firstName, lastName, phone, phoneDigits (phoneDigits10), email, address, service, message, notes (precomputed), externalId, utm_source/utm_medium/utm_campaign, referrer, raw (≤10KB), ip, userAgent, receivedAt: serverTimestamp }.
leads/{'webhook_leads__'+docId} — written by leadBridgeWebhook via mapPublicLeadToLead: userId = resolved owner, companyId, firstName/lastName/address/phone/phoneDigits/email, stage 'New', status 'new', source = data.source (e.g. 'Zapier · Facebook Lead Ads') falling back to 'Inbound webhook', notes = data.notes, webLead:false, publicLeadKind 'webhook', publicLeadCollection 'webhook_leads', publicLeadId, utm*/referrer, createdAt/stageStartedAt.
alert_outbox/{auto} — written by lead-alert's recordAlertOutbox with collection 'webhook_leads' (existing ledger, no schema change).
Rate-limit counters land in the existing _rate_limits_ip (Firestore limiter) or Upstash keys rl:inboundWebhook:*.
Money: none. No cost/margin fields anywhere.

**Security:** Auth: 256-bit random per-tenant token presented in a custom header (X-NBD-Webhook-Token) or as the Basic-auth password (mirrors thumbtack.js:89-104, which is proven in prod); stored only as its SHA-256 hash as the doc id, so a Firestore export or console screenshot never leaks a usable credential. Lookup is a doc get by hash — equal cost for hit/miss, no equality timing oracle. Fail closed by construction: no active token doc means 401 for every request; there is no secret whose absence could be mistaken for 'open', and nothing calls a vendor with any value. Tenant scoping: companyId is copied from the token doc and never read from the body; lead-bridge resolves the owner through companies/{companyId}.ownerId or the uid==companyId solo convention (lead-bridge-logic.js:92-114) and lead-alert's isNbd gate keys on that companyId (lead-alert.js:56), so a tenant's token can only ever produce that tenant's leads and alerts. Minting is an App-Check-enforced onCall gated by requireTeamAdmin (owner / company_admin / platform admin, with the subordinate-role guard), rate-limited 5/hour/uid; rotation revokes prior tokens. Rules: webhook_leads and inbound_webhook_tokens are explicit `allow read, write: if false` (already covered by default deny; spelled out like thumbtack_leads at firestore.rules:1648-1666); bridged leads inherit the existing /leads tenant rule (166-181). Abuse limits: per-IP 20/min on unknown-token attempts (brute-force/enumeration guard, keyed on the /64), per-token 120/min, 64KB body cap, field caps, unknown keys dropped, raw payload capped at 10KB. Replay/dedupe: deterministic doc id from externalId (Zapier/Make expose the upstream record id) or a canonical-payload hash, create() so a retry is a logged 200 duplicate, never a second card; a `test:true` flag (or X-NBD-Test header) stores but never bridges or alerts, mirroring Thumbtack's isTest. HMAC: not required in V1 — Webhooks by Zapier cannot compute one without a Code step; Make/n8n/Pipedream can. Reserve an optional `X-NBD-Signature: sha256=<hmac(rawBody, tokenDoc.hmacSecret)>` verified only when the token doc carries hmacSecret (V2).
